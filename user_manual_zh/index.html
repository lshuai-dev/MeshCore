    MeshCore LVGL UI 用户操作手册

    本文面向当前项目中启用 LVGL 图形界面的 MeshCore 设备，不以某一块开发板、某一种显示屏或某一个 PlatformIO 编译环境为基线。Heltec T1、T096、T114、Tracker、Tracker V2、V3、V4、V4 R8 等设备家族中，只要固件启用了本项目的 LVGL UI，就可以按本文的通用交互模型操作。

    不同设备的屏幕尺寸、颜色深度、按键数量、触摸能力、传感器和编译功能并不相同。本文用“公共页面”和“条件页面”区分功能，并保留界面中的英文名称，便于与设备屏幕逐项对照。

    1. 手册范围与功能识别

    1.1 适用范围

    本手册覆盖：

    • LVGL UI 的页面、焦点、导航、弹层和输入规则。
    • Home、Recent、Radio、GPS、System 公共页面。
    • Compass、Find Friend、Tracker 条件页面。
    • 消息、Advert、GPS、离线地图、RTC、电源管理和 Companion 的用户可见行为。
    • 常见故障的判断与恢复步骤。

    本手册不覆盖：

    • PlatformIO 安装、固件编译和烧录。
    • OLED、纯命令行、无 LVGL 的 Repeater 或其他非图形界面。
    • LoRa 天线设计、射频匹配和法规认证。
    • Companion 协议的字段级实现。协议细节见 Companion Protocol。

    1.2 公共页面和条件页面

    页面或能力 可用条件 用户如何识别
    Home LVGL UI 公共页面 导航中显示 Home
    Recent LVGL UI 公共页面 导航中显示 Recent
    Radio LVGL UI 公共页面 导航中显示 Radio
    GPS LVGL UI 公共页面 页面始终可以存在；无 GPS 时显示不可访问状态
    System LVGL UI 公共页面 导航中显示 System
    Compass 固件包含指南针功能 导航中显示 Compass
    Find Friend 当前项目中随指南针功能一同启用 导航主区域或独立入口显示 Find Friend
    Tracker 固件包含地图功能 导航中显示 Tracker
    完整 Quick Ping 特定触摸优先构建 顶部下滑后出现目标、预设和输入控件
    LNA 硬件和固件支持 LNA 控制 Radio 页面显示 LNA 开关
    Buzzer / 音量 硬件和固件支持蜂鸣器 System 页面显示对应控件

    如果本文描述的页面或控件没有出现在设备上，通常表示当前固件未包含该能力，而不是操作失败。判断优先级应为：

    1. 当前屏幕实际显示。
    2. 设备按键丝印和硬件说明。
    3. 固件发布说明或编译配置。
    4. 本手册中的常见映射示例。

    2. 首次使用

    2.1 启动前检查

    1. 先安装与设备频段匹配的 LoRa 天线，再开机或进行发射操作。
    2. 连接电池或 USB/外部电源，确认供电稳定。
    3. 需要 GPS 时，确认设备确实带 GPS 模块并正确安装天线。
    4. 需要 Tracker 时，提前准备 SD 卡和离线 PNG 地图瓦片。
    5. 开机后进入 System > Region，选择符合当地无线电法规的区域预设。

    不要在未安装天线或没有合适假负载的情况下长时间发射。Region 决定 LoRa 区域和频段参数，不能仅根据其他设备的设置盲目选择。

    2.2 界面组成

    LVGL UI 通常由以下区域组成：

    • 顶部栏：显示当前页面标题，以及电池或连接类状态。
    • 页面内容区：显示状态、列表、开关、下拉框和操作行。
    • 导航层：以网格面板或径向面板选择页面。
    • 操作层：显示当前页面可用的命令，例如发送消息或指南针校准。
    • 模态层：显示确认框、键盘、参数选择器、提示和错误信息。

    弹层打开后，输入会优先交给最上层。要回到页面，需逐层执行“返回”，不要假定一次返回一定直接回到 Home。

    2.3 建议检查顺序

    设备启动后通常进入 Home。建议按实际可用功能检查：

    1. 在 Home 确认节点 ID 和 Companion 状态。
    2. 在 System 设置正确的 Region。
    3. 在 Radio 核对频率、带宽、扩频因子和发射功率。
    4. 如果有 GPS，在 GPS 打开 gps 并等待 fix。
    5. 如果有指南针，在 Compass 检查航向并完成校准。
    6. 如果有地图，在 Tracker 检查 SD 卡、地图瓦片和本机位置。
    7. 如果使用 Companion，再检查 USB、BLE 或 Wi-Fi 链路。

    3. 通用交互模型

    3.1 操作语义

    不同硬件会把实体按键、键盘或触摸动作转换为同一组 UI 语义：

    语义 作用
    PREV / 上一项 移到上一个焦点、列表项或导航项
    NEXT / 下一项 移到下一个焦点、列表项或导航项
    LEFT / RIGHT 横向移动、修改选择，或由当前控件解释
    ENTER / 确认 打开控件、切换开关、确认选项或执行操作
    ESC / 返回 关闭当前编辑状态或弹层；在页面根层打开导航
    操作菜单 打开当前页面注册的附加命令

    因此，本手册中的“上一项、下一项、确认、返回、操作菜单”是功能语义，不等同于固定 GPIO 或固定按键编号。

    3.2 焦点

    非触摸输入依靠焦点操作。当前可操作控件通常有边框、反色或主题高亮：

    1. 用上一项/下一项移动焦点。
    2. 焦点落在屏幕外时，页面会自动滚动到对应控件。
    3. 长列表会循环或分窗口加载，具体表现取决于页面。
    4. 只读状态行可能参与滚动定位，但按确认不会修改数据。

    如果按确认没有反应，先移动一次焦点，确认高亮是否落在开关、下拉框或 > 开头的操作行上。

    3.3 开关、下拉框和操作行

    开关

    • 焦点落在开关上后执行确认，可以切换开/关。
    • 触摸设备可以直接点击开关。
    • 如果硬件不支持或依赖条件未满足，界面会恢复原状态并显示提示。

    下拉框

    1. 执行确认打开选项。
    2. 用上一项/下一项或方向键浏览。
    3. 再次确认保存当前选项。
    4. 执行返回可取消或关闭下拉框。

    操作行

    • 通常以 > 开头，例如 > Factory reset。
    • 聚焦后执行确认会打开操作或二次确认。
    • 清除、复位等危险操作不会在第一次确认时立即执行。

    3.4 返回和层级

    ESC / 返回按以下顺序处理：

    1. 关闭屏幕键盘或当前编辑状态。
    2. 关闭下拉框、确认框、提示层或操作菜单。
    3. 从子页面返回上层。
    4. 在普通页面根层打开导航面板。
    5. 在导航面板中返回，则关闭导航并回到原页面。

    这意味着双击返回后若只关闭了下拉框，需要再次返回才能打开导航。

    3.5 屏幕唤醒

    屏幕超时关闭通常只关闭显示或背光，不等于设备关机。自动超时模式下，屏幕熄灭后的第一次按键或触摸可能只负责唤醒，不执行原本的点击、确认或返回动作；待屏幕亮起后再操作一次。

    4. 输入方式

    4.1 单实体按键的常见映射

    按键动作 常见语义
    单击 下一项
    双击 返回
    三击 打开操作菜单
    长按 确认

    单键设备没有独立“上一项”时，通常通过持续单击在可用焦点间循环。

    4.2 双实体按键的通用映射

    以下是框架默认双键输入适配。本文称为“按键 1”和“按键 2”，实际名称以设备丝印为准。

    按键动作 按键 1 按键 2
    单击 上一项 下一项
    双击 返回 打开操作菜单
    长按 确认 确认

    部分板级实现会覆盖多击映射，例如：

    • 两个按键双击都作为返回。
    • 按键 1 三击作为向左。
    • 按键 2 三击作为向右。

    常见多击识别窗口约为 350 ms，长按阈值约为 1000 ms；这些是当前框架的常用默认值，板级配置可以覆盖。不要只凭按键数量推断映射，应先做一次第 4.5 节的操作自检。

    4.3 键盘

    带键盘或键盘输入桥接的设备通常使用：

    键 语义
    方向键 移动焦点或修改当前选择
    Enter 确认
    Esc 返回或关闭最上层

    字母和数字键只有在屏幕键盘、文本输入或对应页面明确接收文本时才有效。

    4.4 触摸和手势

    触摸构建可能支持以下动作：

    动作 常见结果
    点击 聚焦、切换开关、打开下拉框或执行操作
    在可滚动内容上上下拖动 滚动页面或列表
    从左边缘向右滑 打开导航
    在导航面板上向左滑 关闭导航
    从顶部向下滑 触摸优先构建打开 Quick Ping；其他构建可能打开操作菜单
    普通左右滑 仅在支持顺序切页的构建中切换相邻页面
    点击顶部标题 仅在启用顶部触摸入口的构建中打开或关闭导航
    在 Tracker 地图区域拖动 平移地图，不触发页面切换

    网格导航构建不保证普通左右滑可以切页。地图、滚轮、下拉列表和可滚动区域会优先处理自己的手势。

    4.5 输入映射自检

    不确定设备按键映射时，可以在不会修改关键设置的页面测试：

    1. 进入 GPS 或 System，短按各按键，观察焦点向哪个方向移动。
    2. 长按任一按键，确认下拉框是否打开，然后立即返回，不保存修改。
    3. 在普通页面执行返回，确认是否打开导航。
    4. 在 Radio 页面尝试操作菜单，确认能否看到 send message 和 send advert。
    5. 记录实际映射，后续按语义使用。

    5. 页面导航

    5.1 两种导航外观

    导航方式 外观和特点 操作
    网格导航 页面图标按网格排列，条件功能可能放在独立底部入口 移动选择，确认进入，返回关闭
    径向导航 页面图标沿圆环或弧形排列，可以顺序预览 前后/左右移动，确认进入，返回关闭

    导航外观由固件构建决定，不能在 System 中切换。

    5.2 打开和关闭导航

    可用入口取决于输入设备：

    • 在普通页面根层执行返回。
    • 触摸设备从左边缘向右滑。
    • 部分触摸构建点击顶部标题。

    导航打开后：

    1. 当前页面通常作为初始选中项。
    2. 用方向、上一项/下一项或直接点击选择页面。
    3. 执行确认进入。
    4. 执行返回或反向滑出关闭导航，仍停留在原页面。

    5.3 页面顺序

    框架的逻辑页面顺序为：

    Home
Recent
Radio
Compass（可选）
Find Friend（可选）
GPS
Tracker（可选）
System

    网格中的视觉排列可能与该顺序不同，Find Friend 也可能显示为独立入口。需要进入指定页面时，以导航图标和标题为准。

    6. 公共页面

    6.1 Home

    Home 是设备状态首页，可能显示：

    • ID: ...：本节点 ID。
    • MSG: ...：未读消息数量，不是历史消息总数。
    • COMP: idle：Companion 链路当前空闲。
    • Pin: ...：等待 Companion 配对时的 PIN。
    • < Connected >：Companion 已连接。
    • 顶部电池图标：电池电量估算。

    Recent 不是消息历史页。收到新消息后，未读计数可能增加，消息内容由预览弹层或 Companion 客户端读取。

    6.2 Recent

    Recent 显示最近听到的节点 Advert，通常每行包含：

    • 节点名称。
    • 距离上次听到该 Advert 的时间，例如秒、分钟或小时。

    用上一项/下一项浏览列表，触摸设备也可上下滚动。列表时间依赖 RTC；RTC 未同步时，节点“多久前听到”的显示可能不准确。

    该页面不显示完整消息内容、消息发送历史或精确节点距离。

    6.3 Radio

    Radio 用于查看当前无线参数和最近一次接收状态：

    字段 含义
    FQ 当前工作频率
    SF LoRa 扩频因子
    BW 带宽
    CR 编码率
    TX 发射功率
    NF 噪声底
    RSSI 最近一次有效接收的信号强度
    SNR 最近一次有效接收的信噪比

    尚无有效接收时，RSSI 和 SNR 可能显示 --。它们是无线链路测量值，不代表地图距离。

    硬件支持时还会显示 LNA 开关。切换失败并提示 LNA unavailable，表示当前硬件状态或固件不接受该操作。

    Radio 页面的操作菜单通常包含：

    • send message
    • send advert

    LoRa 区域预设在 System > Region 中设置。

    6.4 GPS

    GPS 页面可能包含以下控件：

    • gps：GPS 功能总开关。
    • location share：是否在节点 Advert 中分享位置。
    • adv interval：位置 Advert 周期，仅在位置分享开启时显示。
    • gps track：GPS 轨迹记录，仅在固件包含轨迹能力时显示。

    页面还会显示卫星数、纬度、经度、海拔和速度。主要状态含义如下：

    屏幕状态 含义
    can't access gps 固件无法访问 GPS 硬件
    gps off GPS 功能已关闭
    gps sleep GPS 已启用，但当前未被电源策略供电
    no fix GPS 正在工作，尚未获得有效定位
    fix 已获得有效定位

    打开 location share、gps track 或需要连续定位的功能时，框架会尝试自动启用 GPS。硬件不可用时会恢复开关并提示 gps unavailable。

    位置分享

    location share 会把本机位置写入节点 Advert，使其他节点能够保存并显示本机的最近位置。常见 adv interval 选项为：

    • 30s
    • 1m
    • 3m
    • 5m
    • 10m

    实际选项以屏幕下拉框为准。周期越短，位置更新越及时，但 GPS、发射活动和电池消耗通常越高。

    位置分享有明确隐私影响：

    • 只在可信 Mesh 网络和必要场景中开启。
    • 离开测试区域或不希望暴露位置时及时关闭。
    • 调大 Advert 周期只能降低更新频率，不能消除位置暴露。

    GPS 轨迹

    打开 gps track 后，设备在获得有效定位时写入内部轨迹文件：

    • 第一条有效定位作为起点。
    • 后续位置通常至少移动约 50 m 才新增轨迹点。
    • 当前实现最多约 600 个点，达到上限后自动停止。
    • 关闭 gps track 会结束当前轨迹文件。
    • 当前 LVGL UI 没有本地轨迹浏览页。

    轨迹通过 Companion JSON 协议分批导出。导出前先关闭 gps track；仍在记录时，请求会返回 recording_active。

    6.5 System

    System 集中显示设备级设置。控件会按硬件和构建能力增减。

    Region

    Region 包含：

    • Custom/fwd：当前自定义或 Repeat 状态入口，不是普通地区预设。
    • 固件提供的 LoRa 区域/频段预设。

    选择预设后会保存无线配置。若 Repeat Mode 正在运行，改变 Region 会关闭转发，避免旧转发参数继续生效。

    必须选择符合设备射频能力和当地法规的区域。

    Enable Repeat Mode

    打开 Enable Repeat Mode 后，界面会要求选择转发频率。当前实现常见候选为 433 MHz、869 MHz 和 918 MHz，但实际可选和可用范围取决于构建、射频芯片及法规。

    以下提示表示参数未被接受：

    • Frequency unsupported
    • Invalid radio params
    • Repeat mode unavailable

    Repeat Mode 会改变设备网络角色并增加无线活动，不需要时应关闭。

    Screen off

    Screen off 设置自动关闭显示的时间。常见选项为 10、15、20、25、30 秒，实际值以当前下拉框为准。

    屏幕关闭不等于设备关机，LoRa、GPS 轨迹、位置分享和 Companion 等后台任务可继续运行。并非所有构建都提供独立 Power off 菜单。

    Bluetooth

    Bluetooth 控制固件暴露的蓝牙或 Companion 链路能力，不是 LoRa 无线开关。实际传输介质可以由构建配置为 USB、BLE 或 Wi-Fi；因此：

    • 不要用该开关判断 LoRa 是否工作。
    • USB-only 构建不会因为手机开启蓝牙而变成 BLE 设备。
    • BLE 配对 PIN 以本次会话 Home 页面显示为准。

    Buzzer

    只有设备定义了蜂鸣器时才显示 Buzzer。支持音量控制的设备还会显示音量调节控件。关闭蜂鸣器只影响提示音，不关闭消息接收。

    7. 条件页面

    7.1 Compass

    Compass 仅在固件包含指南针功能时出现，页面可能显示：

    • 指南针盘和航向指针。
    • HDG：当前航向角。
    • Q：校准质量。
    • 磁场 X、Y、Z 分量。

    常见状态：

    状态 含义
    No compass 未发现指南针模块或硬件不可访问
    Starting... 传感器正在启动，尚无稳定航向
    Q 较低 当前校准质量不足，航向可能偏差较大

    指南针校准

    校准质量不足时，界面可能自动打开校准流程；也可以在 Compass 的操作菜单选择 calibrate：

    1. 远离磁铁、扬声器、大电流导线和大块金属。
    2. 按屏幕提示将设备缓慢做“8”字运动，并改变各轴朝向。
    3. 观察 Q 和质量连续计数。
    4. 出现 Calibration OK 后关闭校准层。
    5. 若显示 Calibration failed，换到磁干扰更小的位置重试。

    No compass module / Hardware missing 表示缺少硬件，继续转动设备不会解决。Quality OK / Save failed 表示测量质量已达标，但校准参数未能保存，应检查内部存储后重试。

    7.2 Find Friend

    Find Friend 用于根据本机位置、目标位置和指南针航向显示前往目标的相对方向与距离。它需要：

    • GPS 硬件可用。
    • 本机已获得有效 GPS fix。
    • 目标联系人带有效位置，或已输入有效 waypoint。
    • 指南针提供有效航向，才能把地理方位转换为设备相对方向。

    启用和模式

    1. 打开 enable。框架会请求 GPS；无法启用时提示 GPS unavailable。
    2. 在 mode 选择：
    3. friend：导航到带位置的联系人。
    4. waypoint：导航到指定经纬度。
    5. 选择目标后观察方向盘和距离。

    Friend 模式

    1. 选择 mode > friend。
    2. 在 friend 下拉框选择联系人。
    3. 若没有可用目标，下拉框显示 (none)。

    联系人位置来自最近保存的 Advert，不是实时连续跟踪。对方关闭位置分享或很久没有更新时，方向和距离仍可能基于旧位置。

    Waypoint 模式

    选择 mode > waypoint 后，可以使用：

    • > use current gps：把本机当前 GPS 坐标保存为 waypoint；没有 fix 时提示 Need GPS fix。
    • > enter lat,lon：手动输入 纬度,经度。

    纬度和经度应使用十进制度数，例如：

    31.230400,121.473700

    纬度范围为 -90 到 90，经度范围为 -180 到 180。保存成功提示 Waypoint saved。

    运行状态

    状态 含义
    starting... 正在等待传感器或方向数据
    need gps 本机没有有效 GPS fix
    nearby 已非常接近目标，不再给出稳定转向
    距离数值 已计算本机到目标的距离

    只有目标、GPS 和航向都有效时，方向指针才具有完整意义。指南针未校准会直接影响相对方向，应先完成 Compass 校准。

    7.3 Tracker

    Tracker 是条件编译的离线地图页面，可以显示：

    • 本机有效 GPS 位置。
    • 已收到且包含有效位置的节点。
    • 当前缩放级别和地图中心。
    • SD 卡与瓦片加载状态。

    地图工具通常包含：

    控件 作用
    - 缩小一级
    + 放大一级
    G 回到当前有效 GPS 位置

    没有有效 GPS 时，G 可能隐藏。用户平移地图后，GPS 更新不会强制把地图拉回中心；执行 G 才重新居中。

    其他节点的地图标记表示设备最后保存的有效位置，不是实时位置流。没有位置的联系人不会绘制。

    8. 消息和 Advert

    8.1 两类操作入口

    当前框架存在两种常见入口：

    入口 常见构建 能力
    页面操作菜单 单键、双键、键盘或普通手势构建 当前页面命令，例如发送消息、Advert、校准
    完整 Quick Ping 特定触摸优先构建 直接选择目标、预设消息或自定义消息

    Quick Ping 并不是所有 LVGL UI 的公共页面。设备只有页面操作菜单时，应从 Radio > send message 进入发送流程。

    8.2 发送消息

    通用发送流程为：

    1. 打开 Radio 的操作菜单。
    2. 选择 send message。
    3. 选择接收目标：
    4. broadcast：广播。
    5. group：选择频道。
    6. personal：选择联系人。
    7. 选择预设消息或 custom...。
    8. 输入自定义消息时，完成键盘输入并确认。

    预设消息包括：

    hi
bye
yes
no
ok

    完整触摸 Quick Ping 还可以把目标直接设为 advert。advert 会发送本机 Advert，不发送文本。

    8.3 发送结果

    • Queued：消息已加入本机发送队列，不代表所有目标已经收到。
    • Failed：请求未能加入发送流程或发送准备失败。
    • No group channels：没有可用群组频道。
    • No contacts：没有可用个人联系人。
    • Message too long：消息超过当前限制。

    当前自定义消息上限为 120 个字符，空消息不会发送。

    8.4 发送 Advert

    Advert 用于发布本机节点信息，并可在位置分享开启时携带位置。可以通过：

    • Radio > 操作菜单 > send advert
    • 完整 Quick Ping 中的 advert

    Advert 不是聊天消息。频繁手动发送会增加信道占用和电量消耗。

    9. Tracker 地图准备

    9.1 地图格式的正式名称

    当前 Tracker 地图格式可正式称为：

    Web Mercator（EPSG:3857）XYZ Raster Tiles，也称 Slippy Map PNG Tiles。

    它不是一张完整大图，而是一组按缩放级别 z、横向瓦片编号 x 和纵向瓦片编号 y 组织的 PNG 图片。地理位置由目录路径决定，图片内部不需要额外坐标元数据。

    9.2 文件硬性要求

    • 投影：Web Mercator，EPSG:3857。
    • 瓦片编号：XYZ，不能使用 Y 轴翻转的 TMS 编号。
    • 图片格式：PNG，小写扩展名 .png。
    • 瓦片尺寸：256 x 256 像素。
    • 缩放范围：2 到 18。
    • 推荐颜色格式：常规 8-bit RGB 或 RGBA PNG。
    • 文件名：z、x、y 必须是十进制数字。

    建议避免交错 PNG、异常大色深或非标准编码，以降低嵌入式 PNG 解码失败的概率。

    9.3 SD 卡目录

    推荐布局如下。这里“SD 卡根目录”指插卡后看到的根目录，不需要再创建名为 SD 的文件夹。

    SD 卡根目录/
└── maps/
    └── osm/
        └── 13/
            └── 6812/
                └── 3351.png

    路径规则：

    maps/{style}/{z}/{x}/{y}.png

    当前实现还兼容：

    tiles/{z}/{x}/{y}.png
maps/{style}/{z}/{x}/{y}/{y}.png

    style 建议使用 osm，并只使用字母、数字、下划线、连字符和点号。

    9.4 自动识别

    默认样式为 osm，默认缩放级别为 13。进入 Tracker 后，固件会扫描 SD 卡：

    • 优先查找已保存样式和 maps/osm。
    • 已保存样式不存在时，尝试其他包含有效瓦片的样式目录。
    • 已保存缩放级别没有瓦片时，在 2 到 18 中选择附近可用级别。
    • 也可以识别没有样式层的 tiles/{z}/{x}/{y}.png。

    地图中心、缩放和样式偏好保存在内部文件系统，PNG 文件保存在 SD 卡，两者彼此独立。

    9.5 不能直接使用的文件

    以下内容不能直接作为 Tracker 地图：

    • 一张完整的 JPG 或 PNG 大图。
    • JPG 瓦片。
    • MBTiles 数据库。
    • PBF 矢量瓦片或 OSM PBF 数据。
    • GeoTIFF。
    • TMS 编号瓦片。
    • 只有 z/x/y 目录但没有 PNG 图片的空地图包。

    如果手头只有大 PNG、MBTiles、PBF 或 GeoTIFF，必须先重投影、切片并导出为符合目录规则的 XYZ PNG。

    9.6 免费数据和 PNG 来源

    可从以下公开资源开始准备地图，但“免费访问”不等于允许无限批量下载：

    来源 地址 得到的内容
    OpenStreetMap 数据 planet.openstreetmap.org 原始 OSM 数据，需要自行渲染
    Geofabrik download.geofabrik.de 分地区 OSM PBF，需要自行渲染
    BBBike Extract extract.bbbike.org 自选区域数据，需要转换
    QGIS qgis.org 可重投影、处理和导出地图
    Mobile Atlas Creator mobac.sourceforge.io 可制作离线瓦片包，数据源授权需单独确认

    技术上，XYZ 服务可以直接返回 PNG，例如：

    https://tile.openstreetmap.org/{z}/{x}/{y}.png
https://tile.opentopomap.org/{z}/{x}/{y}.png

    这些公共服务通常限制批量抓取、离线预取、请求速率和使用场景。OpenStreetMap 标准瓦片服务尤其不应作为大范围离线地图包的批量下载源。实际制作地图前，应阅读对应服务当前的 Tile Usage Policy、授权和署名要求。

    稳妥的免费方案是下载允许离线处理的 OSM 数据，在本地渲染并导出所需区域和缩放级别的 XYZ PNG。固件不会自动联网下载地图。

    9.7 容量估算

    某一级缩放中，区域覆盖的瓦片数量约为：

    瓦片数 = 横向 x 数量 × 纵向 y 数量
容量约等于所有瓦片 PNG 文件大小之和

    缩放级别每提高一级，同一区域的瓦片数量通常约增至 4 倍。只准备实际活动区域和需要的缩放级别，可显著减少 SD 卡容量、扫描时间和文件数量。

    10. RTC 时间同步

    当前项目没有使用 NTP、SNTP 或 Wi-Fi configTime() 自动校时。RTC 主要通过以下方式获得时间。

    10.1 从联系人时间恢复

    设备启动并加载联系人后，会参考联系人记录中最新的本地修改时间恢复 RTC。该机制主要维持排序、去重和时间戳单调递增，不能保证绝对时间准确。

    10.2 Companion 设置时间

    Companion 可以发送 CMD_SET_DEVICE_TIME。固件只接受不早于当前 RTC 的时间，尝试把时间调回过去会被拒绝。

    这是带 Companion 设备最直接的校时方式。

    10.3 GPS 自动校时

    GPS NMEA 提供连续有效时间样本后，固件会写入 RTC。自动校时完成后通常约 30 分钟才允许再次自动校时。GPS 提供 UTC，设备内部时间戳也按 UTC 处理。

    10.4 CLI 或串口

    支持 CLI 的构建可以使用：

    clock
clock sync
time <unix_epoch_seconds>
    • clock：查询当前 UTC。
    • clock sync：使用发送方时间同步。
    • time：使用 Unix epoch 秒数设置。

    这些入口同样不允许时间倒退。

    10.5 时间不准确时

    外置 RTC、ESP32 RTC 或易失性 RTC 负责保存和提供当前时间，但它们本身不是网络时间源。设备刚恢复出厂、没有有效联系人、未连接 Companion 且 GPS 尚未提供有效时间时，RTC 可能不准确。

    建议优先级：

    1. Companion 设置时间。
    2. GPS 自动校时。
    3. CLI/串口手动设置。
    4. 联系人时间恢复仅作为保底。

    11. 电源和屏幕行为

    当前项目由 PowerMgr 协调电池、外部供电、背光和 GPS 供电需求。用户不直接操作 PowerMgr，但会看到以下结果。

    11.1 电池和外部供电

    • 顶部电池图标显示估算电量。
    • 参考默认实现约每 10 秒采样一次电池电压。
    • 参考默认实现约每 1 秒检测一次 USB/外部供电状态。
    • 参考默认电量曲线把约 3000 mV 到 4200 mV 映射为 0% 到 100%。

    以上是当前框架默认值或参考值，板级实现可以覆盖采样周期、电压曲线和外部供电检测。电池图标不是精密容量计；发射、GPS、背光和 SD 卡访问都会造成电压波动。

    11.2 GPS 供电需求

    GPS 不一定始终供电。以下功能会请求 GPS：

    • GPS 页面在前台。
    • Tracker 页面在前台。
    • location share 进入位置 Advert 时间窗口。
    • gps track 正在记录。
    • Find Friend 等需要连续定位的条件功能。

    只有 GPS 已启用、硬件可用并且存在有效需求时，PowerMgr 才会保持 GPS 供电。供电启动失败时，参考默认重试间隔约为 1 秒。

    屏幕关闭后，前台 GPS/Tracker 需求通常保留约 30 秒宽限期；若没有其他需求，宽限期结束后 GPS 才可能休眠。因此离开地图或屏幕熄灭后，GPS 不立即断电属于预期行为。该宽限时间可由构建覆盖。

    11.3 省电建议

    1. 不需要共享位置时关闭 location share。
    2. 轨迹结束后关闭 gps track，让轨迹文件正常结束。
    3. 不需要导航时关闭 Find Friend。
    4. 不查看地图时离开 Tracker。
    5. 把 Screen off 设置为合适的短时间。
    6. 不需要转发时关闭 Enable Repeat Mode。
    7. 不使用 Companion 时关闭不需要的无线链路。

    12. Companion 使用

    12.1 连接状态

    在 Home 查看：

    • COMP: idle：链路已就绪但当前空闲，或尚未建立会话。
    • Pin: ...：等待需要 PIN 的配对。
    • < Connected >：已连接。

    BLE 配对时使用本次会话屏幕显示的 PIN，不要假定固定 PIN。连接介质由固件决定：

    • USB Companion：通过 USB 串口。
    • BLE Companion：通过手机或电脑的 BLE。
    • Wi-Fi Companion：通过对应网络配置。

    12.2 Companion 可以完成的工作

    • 同步联系人、频道和消息。
    • 读取未读消息。
    • 发送个人、群组和广播消息。
    • 请求发送本机 Advert。
    • 设置或读取设备时间。
    • 在 GPS 轨迹结束后分批导出轨迹。

    具体帧格式、JSON 命令、服务 UUID 和错误码见 Companion Protocol。

    12.3 连接异常

    • BLE 搜不到设备：确认固件确实包含 BLE Companion，而不是 USB-only 构建。
    • PIN 不正确：使用当前屏幕 PIN，并清除客户端旧配对记录后重试。
    • USB 无响应：检查数据线是否支持数据传输、串口权限和端口选择。
    • Wi-Fi 不可用：确认当前固件包含 Wi-Fi Companion 及必要网络配置。
    • 频繁断开：避免在 Factory reset 或重启过程中保持会话，客户端应支持重连。

    13. 数据清除和恢复出厂

    System 中的两个清除操作都会二次确认：

    操作 主要影响 是否重启 是否删除 SD 地图
    Clear data 清除联系人、消息文件和相关用户数据，清零未读消息 否 否
    Factory reset 格式化内部文件系统并恢复内部配置 是 否

    Factory reset 会删除内部保存的节点偏好、地图中心、缩放、样式和其他内部文件。SD 卡位于独立存储介质，maps、tiles 和 PNG 文件不会被该操作格式化。

    执行前应通过 Companion 导出需要保留的联系人、频道、消息和 GPS 轨迹。清除后不能从本地 UI 撤销。

    14. 常见问题

    14.1 按键只移动焦点，不能确认

    • 短按通常负责移动，长按通常负责确认。
    • 确认焦点是否落在可操作控件上。
    • 屏幕刚被唤醒时，第一次按键可能只唤醒显示。
    • 按第 4.5 节重新识别当前设备映射。

    14.2 返回后没有打开导航

    当前可能还有下拉框、键盘或弹层。继续逐层返回，直到普通页面根层，再执行返回。触摸设备也可从左边缘向右滑。

    14.3 找不到某个页面

    • Compass 和 Find Friend 需要指南针功能。
    • Tracker 需要地图功能。
    • GPS 页面存在不代表一定装有 GPS 硬件。
    • 网格导航中的条件入口可能位于底部或不同位置。

    以当前导航显示为准。

    14.4 GPS 一直显示 no fix

    • 把设备移到室外开阔位置。
    • 确认 GPS 天线、串口和供电。
    • 保持 GPS、Tracker 或其他 GPS 需求功能活动，等待冷启动。
    • gps off 表示需要打开 GPS。
    • gps sleep 表示当前没有有效供电需求。
    • can't access gps 应重点检查硬件和固件能力。

    14.5 位置分享开启但其他节点看不到

    • 先确认本机 GPS 状态为 fix。
    • 等待下一个 adv interval。
    • 检查 LoRa Region 和链路参数是否一致。
    • 对方看到的是最近收到的 Advert，不是实时连接。

    14.6 Find Friend 没有方向

    • 确认 enable 已打开。
    • 确认本机 GPS 为 fix。
    • Friend 模式确认联系人带有效位置。
    • Waypoint 模式确认经纬度已保存。
    • 在 Compass 确认硬件可用并完成校准。
    • 非常接近目标时显示 nearby，不再给出稳定转向。

    14.7 Compass 航向不稳定

    • 远离磁铁、音箱、钢制桌面和大电流线缆。
    • 重新执行“8”字校准。
    • 观察 Q 是否达到稳定质量。
    • 改变设备安装姿态后，可能需要重新校准。

    14.8 地图显示 noSD 或 Map unavailable

    按以下顺序检查：

    1. SD 卡是否被识别。
    2. maps 或 tiles 是否直接位于 SD 卡根目录。
    3. 扩展名是否为小写 .png。
    4. 瓦片是否为 256 x 256 PNG。
    5. z 是否在 2 到 18。
    6. x、y 是否为十进制数字。
    7. 是否使用 XYZ，而不是 TMS。
    8. 当前地图中心附近是否真的有对应瓦片。
    9. 是否等待 SD 探测、目录扫描和 PNG 解码完成。

    14.9 地图没有本机标记

    本机标记依赖有效 GPS fix。先在 GPS 确认状态为 fix，再回到 Tracker 并执行 G。如果地图曾被手动平移，不会自动回到本机位置。

    14.10 地图没有其他节点

    • 对方必须在 Advert 中分享有效位置。
    • 本机必须收到并保存对应节点。
    • 标记表示最后保存的位置，可能已经过期。
    • Recent 能看到节点不代表该 Advert 一定带位置。

    14.11 消息发不出去

    • group 需要至少一个群组频道。
    • personal 需要至少一个联系人。
    • 自定义消息不能为空且不能超过 120 个字符。
    • Queued 只表示进入发送队列。
    • advert 发送节点 Advert，不发送文本。

    14.12 Recent 时间不正确

    先通过 Companion、GPS 或 CLI 同步 RTC。联系人时间恢复只保证时间戳尽量单调，不能替代准确校时。

    14.13 Repeat Mode 无法启用

    先选择合法 Region，再选择硬件支持的频点。出现 Frequency unsupported、Invalid radio params 或 Repeat mode unavailable 时，应检查固件配置、射频芯片和当地法规，不要反复强制启用。

    14.14 Factory reset 后地图不见了

    SD 卡 PNG 没有被删除，但内部地图中心、缩放和样式偏好已重置。重新进入 Tracker 并等待扫描；仍显示 noSD 时按第 14.8 节检查。

    15. 构建差异速查

    差异 可能表现 使用原则
    屏幕尺寸和色深 控件密度、字体、滚动范围不同 以焦点和标题识别功能
    单键/双键 多击映射不同 先做输入自检
    触摸 可能有边缘手势和完整 Quick Ping 无触摸时使用焦点与操作菜单
    网格/径向导航 页面排列和连续切页能力不同 通过导航图标选页
    GPS 硬件 fix、轨迹、位置分享可用性不同 看 GPS 状态而非只看页面是否存在
    指南针 Compass、Find Friend 可用性不同 先校准，再使用方向
    地图 Tracker 是否出现 需要 SD 卡 XYZ PNG
    LNA、Buzzer 控件可能不显示 不显示即当前构建不可用
    Companion 介质 USB、BLE 或 Wi-Fi 使用与固件匹配的客户端链路
