# UI 固定内存优化记录

## 本轮实施范围

只修改 UI/显示适配层，不改变 MeshCore 协议、联系人存储、加密或收发队列。
不新增运行期动态队列，不缩小 LVGL 80 KiB 内存池，未编译。

- 状态派发器不再为 11 类事件各保存一个最大尺寸联合体：保留五种实际载荷的固定快照，
  无载荷通知只使用 pending 位图。派发前仍复制为局部事件，清除位后调用接收方，
  保留同类事件合并及回调期间重新发布事件的处理方式。
- 焦点回调利用对象已有事件描述符的非空 user_data 判断是否已绑定，避免删除后重新添加。
  对象已经属于目标组时不再次加入；不新增绑定记录数组。
- 单目标弹窗重新进入时复用同一个组节点，显式恢复焦点。其他成员变化的组仍按原逻辑重建。
- 增加 ht_label_create_static，明确借用文本生命周期并使用 CLIP。
  GPS、GPS Track、LNA 固定标题已迁移。动态临时字符串与 LONG_DOT 标签不能直接替换。

## 进一步检查结论

1. 多控件弹窗组：触摸消息列表、Quick Ping 会改变成员或可见状态，不能简单删除 clear。
   LVGL 遍历会跳过隐藏/禁用项，但当前焦点仍需主动迁移，默认焦点也必须有效。
   建议后续按弹窗单独实现固定顺序成员池，并验证空列表、隐藏祖先、禁用项、返回及编辑模式。
2. 页面焦点表：每页 16 项，每项两个指针；32 位目标上数组为 128 字节。
   全局缩容可能丢失可选项，不建议。若测得收益必要，可让具体页面提供定长表，
   基类仅持有指针与容量，避免模板复制代码；须列出各构建配置的最大控件数量。
3. 主题：已经存在触摸/非触摸编译期条件，不应把源码分支数直接当成 Flash 浪费。
   不建议直接关闭 LV_DRAW_COMPLEX；先用新 ELF 定位实际存活符号，再核实圆角、遮罩及控件需求。
4. 固定文本：可继续逐个迁移生命周期稳定且不使用 DOT 的标签，不修改通用复制接口语义。
5. 延迟队列的 pending/dispatch 两份数组支持回调中再次入队和取消，保留。
   启动创建、空闲暂停的定时器也不为少量空间盲目合并。

## 验证与收益边界

- 本轮只做源码静态检查，实际 Flash/RAM 差值需相同环境编译。
- 状态缓存预计减少常驻 RAM；标签及焦点优化主要减少 LVGL 池内占用/重分配，
  固定池大小不变时不会直接降低链接报告中的池大小。
- 需验证五种载荷正确、无载荷通知、连续同类通知合并、回调内重新发布通知。
- 焦点需覆盖弹窗反复打开/关闭、按键与触摸、默认焦点、隐藏和禁用项、不同屏幕切换。
- 长期测试记录 LVGL max_used、free_biggest_size、frag_pct 和分配失败；稳定前不缩池。

## 固定焦点成员池实施补充

- 触摸发送消息：启动注册全部十行和一个独立空列表焦点对象，退出/重开保留 group。
  空列表隐藏所有行、显示兜底对象；非空时隐藏兜底并恢复模型选中行。
  使用独立对象而非禁用父容器，避免影响子控件；这是少量常驻内存换取稳定性。
- Quick Ping：启动按 target、recipient、message textarea、message dropdown、keyboard
  注册固定成员。退出关闭下拉和键盘但不清空 group，进入不再调用会替换成员的基类 onEnter。
  模式变化仅恢复合法焦点，隐藏收件人行前关闭脱离其对象树的下拉弹出列表。
- 保留原有隐藏/禁用规则。LVGL 顺序遍历跳过这些项，显式焦点恢复仍检查祖先可见性。
  不新增动态数组，不共享不同弹窗的 group；未编译、未做实机测试。

### 焦点容量核对及决策

源码注册上界：Home 3、Radio 5、GPS 7、System 9、Find Friend 10、Tracker 5、Recent 16。
部分项目受功能宏影响而少于此值。保留全局 16 容量，避免 Recent 丢项。
如需继续减少常驻 RAM，应改为页面提供固定表、基类借用表与容量；这属于后续结构调整，
必须覆盖各设备宏组合，不能直接把所有页面容量改成 8 或 10。

### 主题与内存池决策

本轮不关闭 LV_DRAW_COMPLEX，不缩减 80 KiB 池。源码中的触摸分支已由宏控制；
没有确认额外的无损绘制裁剪项，不能把大函数体等同于可删除代码。
待用户编译并实机测量后，再决定池大小和按页面焦点表改造。

验证：发送消息空/非空列表、模式切换、翻页、反复重开、触摸与按键；Quick Ping
切换目标类型、无收件人、展开下拉后隐藏行、键盘打开/关闭、返回后编辑状态。
